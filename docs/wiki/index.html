Overview

Prompt Studio

A local-first Windows desktop workbench that turns images and video into prompts for image and video generation targets. A small vision model describes the media; a larger local model writes the prompt for the selected target. Nothing leaves the machine.

Status: v1 is complete. All planning changes are archived under

openspec/changes/archive/, openspec validate --specs --strict passes for all

12 capabilities, and no active changes remain. The UI system is documented in

docs/ui-system.md; the original contract is preserved in

openspec/changes/archive/2026-11-05-build-local-prompt-studio/.

Workspace

The app opens on Compose. A persistent left rail switches between seven sections:

  • Compose — the default prompt workspace (Describe, Compose, Refine, Batch).
  • Media — import, inspect, and edit source images and video.
  • Library — search saved generations and their provenance.
  • Jobs — watch and control queued work.
  • Presets — edit target instructions and preview the compiled result.
  • Runtime — load models and set the keep-warm policy.
  • Datasets — map, run, and export batches.

Sections stay mounted after the first visit, so moving away and back keeps the selected asset, compose inputs, filters, and editor state in place. The top bar shows the current section and LM Studio health; storage mode and data size sit at the foot of the rail.

What it does

  • Two-stage local pipeline: lfm3-vl-2b describes, a configurable composer

(default gemma4-12b-qat-uncensored-hauhaucs-balanced) writes the prompt.

  • Target presets for mmh3, krea2, krea2 edit, qwen2 edit, plus generic

image/video. Presets are editable and importable.

  • Drag media in from Explorer, edit it non-destructively (crop, mask, trim, fps,

resolution), generate prompts, and drag the result back out.

  • Durable job queue with pause/resume, retry, cancel, reorder, crash recovery,

and a job panel.

  • Prompt library with FTS search, filters, favorites, tags, collections, notes,

ratings, versions/diffs, trash, backup/restore, and JSON/JSONL/CSV/TXT export.

  • Dataset import wizard (TXT, JSON, JSONL, CSV, TSV, image folders), mapping

profiles, dedupe, batch runs, and result export.

  • Per-role model instructions, multi-reference compose, media masking and video

trimming, and batch runs with a worked guide.

  • Talks only to a local LM Studio instance.

Prerequisites

  • Windows 10/11 with WebView2 (preinstalled on current builds).
  • Node.js 24+ and npm 11+.
  • Rust stable with the MSVC toolchain, plus Visual Studio Build Tools with the

C++ workload and a Windows SDK.

  • LM Studio for inference (the app is unusable without it at runtime).

Check the toolchain:

rustc --version
cargo --version

If the commands are missing right after installing Rust, restart the shell so %USERPROFILE%\.cargo\bin is on PATH.

Quick start

  1. Start LM Studio's local server on http://127.0.0.1:1234.
  2. Load or let Prompt Studio load lfm3-vl-2b and your composer model.
  3. Run the app:
npm install
npm run tauri dev
  1. Drag an image or video into the window. The editor opens; apply edits if

needed, choose a preset, and compose. The prompt appears in the workspace and is saved to the library; queued batches also appear in Jobs.

The Vite dev server runs on http://localhost:1420; Tauri opens the desktop window and loads that URL.

Install and portable builds

Build the NSIS installer and the raw release executable:

npm run tauri build -- --bundles nsis

Outputs:

  • src-tauri/target/release/prompt-studio.exe — raw executable.
  • src-tauri/target/release/bundle/nsis/Prompt Studio_0.1.0_x64-setup.exe —

NSIS installer.

  • dist-portable/Prompt Studio/ — portable folder.
  • dist-portable/Prompt Studio_0.1.0_x64-portable.zip — portable zip.

Create or refresh the portable folder after a build:

npm run package:portable

The portable folder contains portable.txt; the app then stores data, cache, config, and the SQLite database under .\data beside the executable. If that folder is not writable, it falls back to the per-user directories and reports the reason in the status panel.

Startup measurements

Measured on the reference machine on 2026-11-05 with the portable build, from process launch until the main window handle exists, then three seconds idle:

RunTime to windowIdle working set
Cold27.61 s29.4 MB
Warm0.09 s29.1 MB

The cold run includes first-run WebView2 initialization and Defender scanning of the bundled 100 MB ffmpeg/ffprobe binaries. First paint is not instrumented separately; the renderer bundle is ~345 KB (102 KB gzipped), so first paint follows window creation closely on warm launches. Re-measure on the target machine before publishing release numbers.

Media sidecars

ffmpeg and ffprobe are bundled, not taken from PATH:

src-tauri/binaries/ffmpeg-x86_64-pc-windows-msvc.exe
src-tauri/binaries/ffprobe-x86_64-pc-windows-msvc.exe

The -<target-triple> suffix is required by Tauri's externalBin mechanism. See src-tauri/binaries/FFMPEG-NOTICE.txt for version and licensing. The build is GPLv3; redistribution obligations apply.

To update, replace both files with a matching static build (keep the suffix) and update the notice. Debug builds write the ffprobe check result to %TEMP%\prompt-studio-sidecar-check.txt.

Testing

  • Renderer tests use Vitest + Testing Library + jsdom.
  • Rust tests use cargo test.
  • LM Studio HTTP behavior is exercised with wiremock; the normal suite needs

no local model server.

  • pipeline::tests::real_models_describe_and_compose is #[ignore]d and can be

run against a live LM Studio with cargo test real_models_describe_and_compose -- --ignored --nocapture. It loads the configured describer and composer models, so close other GPU work first. The 10k library performance test is also ignored; see docs/release-notes.md for the command.
