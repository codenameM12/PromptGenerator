Prompt presets

A preset is the contract between the app and one generation target. It declares the instructions, output schema, legal parameters, limits, and validation checklist used to compile a prompt. Presets are JSON documents with schema: 1.

A complete, validated example lives in example-preset.json.

Adding a target

Most presets are just a prompt guide. Open Presets, choose New, stay on the Guide tab, and fill in:

  • Name — becomes the preset name; the id is slugged from it.
  • Kind — image, video, or image edit. The kind sets the mode, default

sections, checklist, resolutions, negative support, and reference slots.

  • Target description — one line shown in the selector.
  • Prompt guide — the instructions the target expects, in plain text.
  • Prompt character limit — optional; keeps the target's cap.

Save validates the compiled document through the same path as JSON authoring. Editing an existing user preset keeps its id and bumps the patch version when the guide changed. Advanced fields the guide does not expose — parameters, token budgets, examples, output schema — are preserved, except that changing kind resets the kind-specific fields (parameters, sections, resolutions, negative support, reference slots) so an image preset cannot inherit video settings.

Switch to JSON when you need exact control:

  1. Copy example-preset.json.
  2. Change id, name, kind, version, and the prompt/parameter details.
  3. Open Presets in the left rail, choose Import, and select the file.

Imported presets are always user-owned, so they cannot overwrite built-ins.

  1. The editor previews the compiled prompt and reports validation errors.
  2. Save, then choose the preset as the generation target on the Compose view.

Built-in presets are immutable. Use Duplicate to create an editable copy; the copy gets a new id and keeps the original untouched.

Compilation

Compilation merges guidance in increasing priority (global → preset → run), renders the declared sections from the description, applies parameter defaults, validates requested values, enforces character limits, and drops unsupported negative prompts with a warning. Preflight then adds checklist warnings.

mmh3MiniMax-H3 accepts a prompt of at most 7000 characters, an integer duration of 4–15 s, and outputs 768P or 2K. The preset caps prompt characters at 7000, replaces the fixed 5/10 s list with an integer 4–15 s parameter, drops the undocumented frame-rate option, and disables negatives because H3's request schema has no negative field. Output sizes stay advisory because H3 chooses 768P or 2K itself.MiniMax video generation guide: https://platform.minimax.io/docs/guides/video-generation

When a vendor publishes a new cap, update the preset JSON, bump its version, and record the source here; the content hash reseeds built-ins on the next launch.
